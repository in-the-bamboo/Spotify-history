# Spotify-history

# リスニング年表

Spotify から取り寄せた再生履歴のファイルを読み込んで、次の2つを作る1ページのウェブツール。

- **年表**: 月ごとの「主役」アーティストの移り変わり、年ごとのランキング、時間帯・曜日別の聴き方、よく聴いた曲など
- **相関図**: よく一緒に聴くアーティストどうしを線で結んだネットワーク図。グループ分けと、グループごとの伸び

読み込んだファイルは**利用者のブラウザの中だけで処理**され、どこにも送信されない。サーバーは不要。

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | ツール本体。これ1つで動く |

## GitHub Pages で公開する手順

1. GitHub にログインし、右上の「+」→「New repository」で新しいリポジトリを作る。
   - 名前は自由(例: `listening-timeline`)。
   - **Public** を選ぶ(無料プランで Pages を使うには公開リポジトリが必要)。
2. 作ったリポジトリのページで「Add file」→「Upload files」を選び、`index.html`(と `README.md`)をアップロードして「Commit changes」。
3. リポジトリの「Settings」→ 左のメニューの「Pages」を開く。
4. 「Build and deployment」の Source を **Deploy from a branch**、Branch を **main** と **/(root)** にして「Save」。
5. 数分待つと、同じ画面の上部に公開URLが表示される。形は `https://<ユーザー名>.github.io/<リポジトリ名>/`。

このURLを渡せば、誰でも自分の再生履歴を読み込んで使える。

### 注意

- リポジトリに置くのは `index.html` と `README.md` だけにする。**自分の再生履歴(zip や JSON)はリポジトリにアップロードしない**こと。公開リポジトリなので、誰でも中身を見られる。
- 公開せず自分だけで使うなら、`index.html` をダブルクリックしてブラウザで開くだけでも動く。

## 使い方

1. ページを開き、Spotify から届いた zip をそのままドロップする(または「ファイルを選ぶ」)。
2. 中の JSON ファイルを直接選んでもよい。複数の書き出しを一度に選ぶと、重なる記録は1件にまとめる。
3. 「サンプルで見てみる」で、架空のデータを使った表示例を確認できる。

### 読み込める形式

| 形式 | ファイル名 | 期間 |
|---|---|---|
| 拡張版(Extended streaming history) | `Streaming_History_Audio_*.json`、`Streaming_History_Video_*.json` | 全期間 |
| 通常版(アカウントデータ) | `StreamingHistory_music_*.json`、古い書き出しの `StreamingHistory*.json` | 直近約1年 |

両方を一緒に読み込んだ場合、拡張版の期間と重なる通常版の記録は使わない。ポッドキャストは対象外。

## 集計のルール

- 時刻は**ブラウザのタイムゾーン**に変換する(日本の端末なら日本時間)。年は1月1日〜12月31日で区切る。
- 再生時間は、スキップ分も含めた再生時間の合計。
- 再生回数は、30秒以上再生したものだけ数える。30秒未満の割合をスキップ率とする。
- データの日数が年によって違うため、年どうしの比較は「1日あたり」「30日あたり」に直して行う。
- 相関図:
  - 30分以上あいたら別の「ひと続き」とみなして再生を区切る。
  - 同じひと続きの中で一緒に聴かれた頻度からつながりを計算する。3回以上一緒に聴かれた組だけが対象。
  - 再生時間の上位90組が対象。各アーティストから近い順に3組へ線を引く。
  - グループはつながりの強さから自動で分けたもので(モジュラリティ最大化)、ジャンルではない。

数値を変えたい場合は、`index.html` の中の次の箇所を書き換える。

| 変えたいこと | 探す文字列 |
|---|---|
| スキップとみなす長さ(30秒) | `30000` |
| ひと続きを区切る間隔(30分) | `30*60e3` |
| 相関図の対象数(90組) | `slice(0,90)` |
| つながりに必要な回数(3回) | `if(c<3)` |
